# 관리자 상품 카탈로그 관리 계획

## 목표

기존의 상품 **등록** 기능을 확장해, 관리자가 이미 등록한 상품을 목록에서 검색·수정·판매 중지할 수 있게 한다. 결제, 재고 차감, 실제 삭제는 이번 범위에서 제외한다.

## 현재 확인된 범위

- 이미 있음: `/admin/products/new`와 `POST /api/admin/products` 상품 등록.
- 아직 없음: 등록 상품 목록, 이름·브랜드 검색, 수정, 판매 중지/재노출, 관리 화면 진입점.
- 주문은 상품 정보를 JSON 스냅샷으로 보관하므로, 실제 삭제보다 **비활성화**가 안전하다.

## 확정 설계

1. `Product`에 `isActive`를 기본 true로 추가하고 additive Prisma migration을 만든다.
2. 비활성 상품은 Shop·Search·Ranking·For You 등 고객 카탈로그 조회에서 제외한다. 기존 주문·My Posts의 과거 정보는 유지한다.
3. `/admin/products`에 이름·브랜드 검색, 최신순 목록, 페이지 이동, 활성/비활성 상태, 수정 진입점을 제공한다.
4. `/admin/products/[id]/edit`에서 기존 `AdminProductForm`의 검증·이미지 처리 계약을 재사용해 상품을 수정한다.
5. 관리자 전용 GET/PATCH API는 세션과 `ADMIN_EMAILS`를 서버에서 다시 확인한다. 고객 API는 비활성 상품 ID의 직접 접근도 안전하게 404 처리한다.
6. 삭제 버튼은 만들지 않는다. 판매 중지/재노출 토글만 제공하며, 이후 물량·주문·환불 정책이 생긴 뒤 별도 삭제 정책을 결정한다.

## 작업 순서

- [ ] 데이터 모델·migration·상품 조회 필터와 회귀 테스트
- [ ] 관리자 목록/검색/pagination API와 권한·비활성화 mutation 테스트
- [ ] 등록 폼 공통화와 수정 UI·이미지 교체 보상 처리
- [ ] 관리자 목록/수정/토글 desktop·mobile QA
- [ ] 전체 typecheck, lint, test, production build 및 로드맵 갱신

## 완료 기준

- 관리자는 등록 상품을 빠르게 찾아 수정하거나 판매 중지/재노출할 수 있다.
- 고객은 비활성 상품을 목록·검색·직접 URL에서 볼 수 없다.
- 기존 주문 및 공개 콘텐츠의 과거 상품 참조는 깨지지 않는다.
- 실제 삭제·결제·재고·환불 동작은 추가되지 않는다.
