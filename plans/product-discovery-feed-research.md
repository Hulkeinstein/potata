# Potata 제품 발견 피드 조사 보고서

작성일: 2026-10-17. 범위: 공개 공식 자료와 현재 코드에 근거한 제품 방향 제안. 구현·운영 설정·데이터 변경은 포함하지 않는다.

## 결론

**도입에 찬성한다. 다만 Shop을 대체하지 말고 기존 For You를 실제 제품 발견 피드로 발전시키는 것이 좋다.** 사진 한 장을 크게 보며 위아래로 다음 상품을 탐색하고, 마음에 들면 찜하거나 옵션을 선택하는 경험이다. 영상은 콘텐츠와 운영 기반이 준비된 뒤 추가한다.

목표는 단순히 오래 붙잡아 두는 것이 아니라, 고객이 좋아할 상품을 더 쉽게 발견하고 다시 찾도록 만드는 것이다. 체류 시간 증가는 검증할 가설이지 보장된 결과가 아니다. 현재 운영 상품은 마지막 검증 기준 11개이므로, 같은 상품을 몰래 반복하는 무한 루프는 만들지 않는다.

## 조사에서 확인한 패턴

| Instagram Reels | 2020년 공식 발표에서 Reels 상품 태그와 상품 확인 흐름 제공 | 콘텐츠를 보다가 상품 정보를 여는 구조를 참고한다. 과거 발표이며 현재 UAE 계정의 지원 범위를 보장하지 않는다 |
| TikTok Shop | For You의 shoppable video, 상품 showcase, 별도 Shop tab | 발견형 탐색과 검색형 쇼핑을 함께 제공한다 |

| Baymard 상품 목록 연구 | 일반 쇼핑 목록에서는 Load More 방식이 대체로 우수, 상세에서 돌아올 때 위치 복원이 중요 | Shop·검색은 유지하고, 발견형 피드는 별도 실험한다 |

YouTube는 상품 스티커에서 판매처로 이동하거나 연결 상품 목록을 열 수 있다고 설명한다. 제품이 콘텐츠와 관련 있고 식별 가능해야 한다는 지침도 있다. 단순히 상품 링크를 많이 붙이는 것보다, 무엇을 보고 있는지 분명해야 한다. [YouTube 공식 도움말](https://support.google.com/youtube/answer/10191533?hl=en)

Meta의 Reels 상품 태그 발표는 콘텐츠에서 상품 정보를 확인하는 역사적 사례다. 이를 현재 기능·국가 지원이나 Potata의 전환율 근거로 확대 해석하지 않는다. [Meta 공식 발표](https://about.fb.com/ja/news/2020/12/shopping_in_reels/)

TikTok은 발견 피드와 Shop tab을 함께 제공한다. 따라서 Potata도 하나의 탐색 방식만 강요하기보다 목적 구매와 우연한 발견을 나누는 편이 타당하다. 이는 해당 서비스 구조에서 얻은 설계 판단이며, Potata에서 효과가 입증된 것은 아니다. [TikTok Shop 공식 소개](https://newsroom.tiktok.com/introducing-tiktok-shop?lang=en)

TikTok의 공개 추천 설명은 개인별 상호작용뿐 아니라 새로운 콘텐츠의 탐색과 사용자의 관심 조절도 다룬다. Potata가 동일한 알고리즘을 재현할 필요는 없다. [TikTok 추천 설명](https://newsroom.tiktok.com/how-tiktok-recommends-videos-for-you?lang=en)

Baymard의 일반 상품 목록 연구는 끝없는 스크롤을 모든 쇼핑 화면에 적용할 근거가 되지 않는다. 피드에서 상품 상세로 갔다 돌아올 때 같은 상품·위치로 복귀하는 것은 특히 중요하다. [목록 로딩 연구](https://baymard.com/research-articles/number-of-items-loaded-by-default), [위치 복원 연구](https://baymard.com/research-articles/return-same-place)

## 장점과 위험

큰 착용 사진은 스타일·실루엣을 빠르게 전달할 수 있고, 한 화면의 선택지를 줄여 탐색 시작을 쉽게 만들 수 있다. 사진에서 바로 찜하고 옵션을 확인하면 여러 상세 페이지를 오가는 부담도 줄일 수 있다. 이 효과들은 실제 고객 실험으로 확인해야 한다.

반면 상품을 비교하거나 특정 브랜드·가격을 찾는 고객에게는 한 장씩 보는 방식이 느릴 수 있다. 사진 품질이 낮거나 상품이 반복되면 금방 지루해지고, 무거운 영상은 데이터 사용·로딩·배터리 부담을 늘린다. 오래 머물렀더라도 느린 로딩이나 혼란 때문이라면 성공이 아니다.

**기존 Shop·검색·브랜드 목록은 유지하고, 발견 피드에서 언제든 목록 보기로 나갈 수 있게 한다.** 강제 자동 이동, 소리 자동 재생, 허위 인기 수치, 가짜 품절·타이머는 넣지 않는다.

## 현재 Potata에서 재사용할 것

| 기존 기반 | 코드 근거 | 활용과 제한 |
| --- | --- | --- |
| 상품 사진·설명·가격 | `prisma/schema.prisma` Product, `lib/products.ts` | imageUrl·images·KO/EN 설명·AED 가격 재사용. 영상 필드는 없음 |
| 공개 상품 필터 | `lib/products.ts` | isActive 필터 유지. 판매 중지 상품은 피드에도 노출하지 않음 |
| 옵션 재고 | `lib/inventory.ts`, ProductVariant | 색상·사이즈·수량·수동 품절을 동일하게 판정 |
| 구매 제어 | `components/product/ProductPurchaseActions.tsx` | 옵션·수량·찜·cart·공유의 기존 로직을 공통화해 재사용 |
| 찜·장바구니 | `store/wishlist-store.ts`, 기존 cart store/API | 별도 피드 찜·cart DB를 만들지 않음 |
| 페이지 단위 로딩 선례 | `app/api/ootd/route.ts` | cursor와 nextCursor 응답 패턴 참고. 상품 데이터 계약은 별도 필요 |
| 번역·가격 | LanguageProvider, `lib/i18n`, formatPrice | EN/KO UI·언어 유지·가격 표시를 그대로 사용 |
| 테스트 | Vitest, route/UI tests, guarded DB integration | 페이지 경계·재고·권한·복귀 위치 테스트 확장 |

현재 `/for-you`는 `getAllProducts()`를 전달하며 실제 개인별 추천 계산은 없다. `ForYouContent.tsx`의 Sarah·AI 분석·조회한 12개 상품 표현은 데모다. 이 화면을 발견 피드로 교체한다면 데모 문구를 제거하고 실제 정렬 이유만 설명한다.

현재 `/ranking`의 정렬은 판매량이 아니라 가격 내림차순이다. 누적 viewCount와 최근 가상 착장 정보도 개인별 피드 관심 기록과 같지 않다. 이를 판매 인기나 개인화의 증거로 사용하지 않는다.

## 추천하는 첫 화면과 사용 흐름

**세로 이동은 다음 상품, 가로 이동은 같은 상품의 다른 사진**으로 구분한다. 스와이프 외에도 이전·다음 버튼을 제공해 사용법과 키보드 접근을 보완한다. 화면 맞춤 snap은 해제할 수 있게 하고 제스처를 강제로 가두지 않는다. 이미지 크롭으로 옷의 일부가 잘리지 않게 전체 보기 기능을 둔다.

| 화면 영역 | 표시 내용 |
| --- | --- |
| 상단 | 발견 제목, 카테고리·브랜드·가격 조건, 목록 보기·닫기 |
| 중앙 | 실제 상품 사진과 사진 순서 표시 |
| 보조 동작 | 찜, 공유, 관심 없음 |
| 하단 상품 정보 | 브랜드·상품명·실제 AED 가격·품절 상태 |
| 주요 버튼 | 상품 자세히 보기, 옵션 선택 |
| 하단 고정 접근 영역 | Language 드롭다운과 Footer 정보 열기 |

옵션 선택은 화면 아래에서 열리는 패널로 제안한다. 색상·사이즈·수량을 고르고 기존 cart 동작을 사용한다. 옵션을 정하지 않은 상태에서 장바구니로 바로 넣지 않는다. 패널을 닫으면 보던 카드와 포커스로 돌아온다.

피드 자체는 비로그인으로 탐색할 수 있게 하고, 찜·cart의 로그인 요구는 기존 계약을 따른다. 공개 가입 제한을 피드 구현을 이유로 풀지 않는다. 상세나 로그인으로 이동했다 돌아와도 현재 상품·사진 번호·필터를 복원한다.

Footer 언어 선택은 기존 요구사항이므로 무한 스크롤 끝에 밀어두면 안 된다. 하단에 작은 고정 Language 선택을 유지하고, Footer 본문은 버튼으로 펼칠 수 있게 한다. 장바구니 패널·모바일 안전 영역과 겹치지 않는지 검증한다.

현재 모든 상품을 보면 “현재 상품을 모두 봤어요”와 조건 변경·Shop으로 가기를 제공한다. 이미 본 상품을 다시 보려면 사용자가 재탐색을 선택하게 한다. 상품이 충분해지면 같은 구조로 이어서 로딩하되 중복 없는 공급 범위에서만 계속한다.

## 추천 순서와 데이터 수집

첫 버전은 **비개인화 발견 피드**로 시작한다. 판매 중·사진이 있는 상품을 대상으로 카테고리·브랜드가 한쪽에 몰리지 않게 구성하고, 새 상품과 관리자가 선정한 상품을 섞는다. 기본 쇼핑 피드에서는 구매 가능한 옵션이 있는 상품을 우선하며, 전체 품절 상품은 제외하는 안을 권장한다. 상세 공유 링크의 품절 안내는 유지한다.

개인화 전에 카테고리·가격·브랜드 필터와 관심 없음 기능으로 사용자가 직접 방향을 바꾸게 한다. MVP의 관심 없음은 세션 내 숨김으로 시작할 수 있다. 서버에 장기 저장하려면 사용자 범위·삭제·보관 기간을 별도 결정한다.

피드 노출을 기존 `/api/products/[id]/view`에 그대로 보내지 않는다. 스쳐 지나간 카드가 상세 조회수나 HOT 집계를 부풀리면 안 된다. 필요 이벤트는 다음과 같이 구분한다.

- `feed_impression`: 카드가 충분히 보인 노출. 제안 초기 기준은 가시 면적 50% 이상·연속 1초이며 업계 표준 수치가 아니다.
- `feed_engaged_view`: 화면이 활성 상태일 때 유효 체류. 사진과 영상의 기준을 분리한다.
- `product_open`, `wishlist_success`, `cart_success`, `not_interested`: 클릭과 실제 서버 성공을 구분한다.
- 오류·로딩·품절로 막힌 동작은 별도 집계한다.

노출은 session·상품·노출 회차로 중복 방지하고 클라이언트 이벤트를 신뢰된 판매·재고 원장으로 쓰지 않는다. 이벤트 API에 payload 상한·rate limit을 적용하고 봇·관리자 QA를 분석에서 분리한다. 다른 탭·백그라운드 시간은 체류에서 제외한다. 첫 실험은 외부 광고 추적 없이 최소 집계부터 검토하고, 개인별 기록은 목적·보관·삭제·동의 검토 후 도입한다. 키·이메일·신체 정보·fingerprinting을 피드 추천에 무조건 추가하지 않는다.

## 기술 구현 방향

아래 값은 구현 논의를 위한 초기안이며 성능 실측 후 조정한다.

1. 전체 상품을 내려주는 `getAllProducts()` 대신 제한된 상품 feed query/API를 추가한다. 첫 묶음 8개, 최대 요청 20개처럼 서버 상한을 강제하고 응답을 필요한 공개 필드로 제한한다.
2. 고정 정렬에는 정렬 키+id cursor를 사용한다. 다양성·개인화 순서는 단순 cursor만으로 보장되지 않으므로 별도 순서 토큰·만료 정책이 필요하다. 초기 카탈로그는 순서 목록을 작게 제한하고, 커지면 서버의 만료형 피드 세션을 검토한다. 클라이언트가 seen ID 수천 개를 계속 전송하는 방식은 피한다.
3. 동일 탐색 중 순서가 갑자기 재섞이지 않게 한다. 삭제·비활성화·품절된 항목을 다시 검사하고, 누락은 건너뛰되 중복·무한 재요청을 막는다.
4. 현재·인접 사진만 우선 로드하고 긴 목록은 DOM 수를 제한한다. windowing으로 앞 카드를 제거할 때도 키보드 포커스와 복귀 위치를 보존한다.
5. 빠른 연속 스와이프·필터 변경 시 이전 요청 취소 또는 응답 세대 확인으로 오래된 결과를 버린다. 오류는 카드 하단에서 재시도하며 이미 본 목록은 남긴다.
6. cart 추가와 주문 시 가격·활성 여부·옵션 재고를 서버에서 다시 확인한다. 피드에 표시된 재고는 예약이 아니며 스와이프로 재고를 차감하지 않는다.
7. 데스크톱은 강제 세로 전체 화면보다 중앙 카드+정보 패널과 방향 버튼을 우선 검토한다. 모바일은 주소창 높이 변화와 회전·확대에 대응한다.

영상 단계에서는 별도의 media 계약이 필요하다. URL 하나만 Product에 붙이는 것으로 끝나지 않는다. poster·길이·비율·자막·처리 상태·저작권·음원·모델 사용 허락·승인/비공개 상태, 파일 제한과 실제 포맷 검증, 실패·교체·이전 파일 정리까지 포함한다. 외부 임베드는 추적·쿠키·원본 삭제에 의존하고 자체 호스팅은 전송비용이 증가하므로 비교 후 결정한다. 큰 원본 영상은 서버 함수에서 직접 변환하지 않고 별도 처리 구조를 검토한다. 유료 미디어 서비스 도입은 승인 없이 하지 않는다.

영상은 현재 카드만 재생하고 화면 밖·탭 숨김에서는 중지한다. 기본 무음, 재생·정지·음소거 제어, 자막, 저데이터·동작 줄이기 설정을 제공한다. autoplay가 거부되면 재생 버튼으로 전환한다. poster와 preload를 사용하고 최초 주요 이미지는 지연 로드하지 않는다. 브라우저별 지원 차이도 시험한다. [web.dev 영상 지연 로딩](https://web.dev/articles/lazy-loading-video)

키보드로 이전·다음·카드 동작·닫기를 모두 사용할 수 있어야 한다. 스크린리더에 현재 상품과 위치를 알려주되 매 스크롤마다 과도하게 읽지 않는다. feed ARIA는 복사해 붙이지 않고 의미 있는 HTML과 실제 보조기기 시험을 우선한다. [W3C 피드 예제와 주의사항](https://www.w3.org/WAI/ARIA/apg/patterns/feed/examples/feed/)

1차에는 AI 추천 엔진·추천용 벡터 DB·댓글 시스템·라이브커머스·결제·포인트를 새로 만들지 않는다. 기존 공개 출시 보안·법률 gate와 별개로 기능을 개발할 수 있지만, 이 기능이 공개 가입 승인이나 판매 개시를 대신하지는 않는다.

OOTD는 나중에 착장 피드의 좋은 재료가 될 수 있다. 다만 게시물 공개 범위와 사용 권리, 실제 상품 연결, 삭제 동기화가 필요하며 기존 사진을 동의 없이 광고 소재로 전용하지 않는다.

## 성공 측정과 통과 기준

주요 지표는 **피드 방문자 중 상품 상세·찜·cart 성공으로 이어진 비율**이다. 결제가 보류 중이므로 구매 전환율이나 매출 증가를 지금 주장하지 않는다. 사용자당 본 서로 다른 상품 수와 활성 체류 시간은 보조 지표로 둔다.

피드 제공/미제공을 사용자 또는 세션 단위로 고정 배정해 비교하는 실험을 제안한다. 1차 지표·필요 표본·최소 의미 변화는 baseline 확인 후 사전 결정한다. 작은 내부 테스트의 수치로 매출 효과를 일반화하지 않는다. 속도·오류·되찾기 실패가 악화되면 체류가 늘어도 확대하지 않는다.

구현 승인 후 필수 QA는 다음과 같다.

- 상품 0·1·11개와 다중 페이지 테스트 데이터에서 중복·누락·종료 상태 확인.
- 비활성 상품 제외, 전체 품절 정책, 탐색 중 가격·재고 변경과 cart 실패 처리 확인.
- 빠른 스와이프·필터 변경·네트워크 실패 후 재시도 시 잘못된 카드가 섞이지 않음.
- 상세→뒤로·로그인→복귀·언어 전환 후 상품·사진·필터·옵션 입력 보존.
- Footer Language, 키보드·스크린리더, 패널 포커스 복원, 모바일 확대·회전 확인.
- 긴 탐색에서도 DOM·메모리·전송량을 제한하고 불필요한 전체 미디어 다운로드가 없음.
- 노출 중복·백그라운드 체류 제외, 기존 상세 조회수와 feed 이벤트 분리 확인.
- 영상 단계에서 1개만 재생·autoplay 거부·자막·오류·저데이터 모드 확인.

## 일반 보기와 몰입 보기 실행 계획

### 사용자 승인과 범위

- 승인: 기존 For You에서 일반 보기와 몰입 보기를 전환하고, 기존 기능과 겹치지 않게 구현한다.
- 첫 방문은 일반 격자 보기. 모드 선택은 이 브라우저에 기억하며 잘못된 저장값·저장소 사용 불가 시 일반 보기로 안전하게 시작한다.
- 두 모드는 같은 상품 목록·필터·언어·찜 상태를 공유한다. 몰입 보기에서 돌아오면 마지막 상품을 격자에서 찾을 수 있게 한다.
- 기존 For You에 실제 필터는 없으므로 이번에는 기본 카테고리 필터만 추가한다. 별도 Shop 검색·브랜드 관리 기능을 복제하지 않는다.
- Sarah·12개 조회·AI 분석처럼 실제 데이터가 아닌 개인화 문구를 제거한다. 제품명·브랜드 원문과 EN/KO UI는 기존 정책을 유지한다.
- 기존 getAllProducts로 받은 현재 카탈로그를 재사용한다. 이 단계에서는 새로운 feed API·cursor·추천 DB·analytics·영상·옵션 패널을 만들지 않는다. 전체 목록 전송의 대규모 확장 한계는 후속 과제로 남긴다.
- 찜은 기존 HeartButton/store, 일반 격자는 ProductCard, 상세·구매는 기존 상품 상세로 연결한다. 새로운 cart·재고 mutation을 추가하지 않는다.
- finite 목록의 마지막에는 종료 안내를 표시하고 무한 복제하지 않는다. 기존 활성 상품 조회와 품절 표시 계약을 유지하며, 품절 정책 변경은 하지 않는다.
- 운영 DB·환경 변수·외부 서비스·공개 가입·결제·commit·push·배포는 제외한다.

### 기존 기능 대조와 설계

- app/for-you/page.tsx: 기존 서버 상품 조회 유지.
- app/for-you/ForYouContent.tsx: 데모 소개를 실제 발견 안내·보기 전환·카테고리·공유 현재 상품 상태로 대체.
- components/ui/ProductCard.tsx 및 components/common/HeartButton.tsx: 기존 렌더링·찜 동작 재사용. 새 전역 상태나 Wishlist 테이블 없음.
- 몰입 카드는 단일 현재 상품과 제한된 인접 이미지 로딩으로 DOM을 제한한다. 세로 스와이프/이전·다음은 상품, 가로 사진 제어는 해당 상품 사진만 이동한다.
- 보기 전환 버튼은 상단에서 계속 접근 가능하게 한다. 몰입 패널 밖의 공통 Footer를 유지하고 언어 선택까지 이동할 수 있게 한다. 페이지 전체 스크롤 잠금 금지.
- 상세로 이동 전 탐색 상태를 세션 범위로 기억하고, 동일 목록에 상품이 있으면 복귀한다. 없는 상품은 첫 유효 상품으로 대체하며 DOM을 임의 조회한 오래된 id를 신뢰하지 않는다.
- 키보드 조작은 입력/선택 상자의 화살표를 가로채지 않는다. reduced-motion·명확한 버튼 이름·빈 상태·이미지 실패 대체 표시를 제공한다.
- Metis 검토 반영: 저장 모드 hydration 전후 레이아웃 점프를 완화하고, 복원은 category/productId/photoIndex를 함께 다룬다. 마지막 다음 버튼은 비활성화한다. 이미지 로딩 상한은 몰입 카드에 한하며 기존 격자 lazy loading은 유지한다. cursor·브랜드/가격 필터·관심 없음·cart 패널·분석 이벤트는 이번 완료 기준에서 제외한다.
- 시각 방향: 기존 Potata 검정/네온과 제품 중심의 절제된 editorial 스타일 유지. 새 폰트·패키지·브랜드 리디자인 없음.
