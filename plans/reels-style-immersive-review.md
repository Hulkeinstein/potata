# Potata 몰입 보기의 Reels형 전환 개선 보고서

작성일: 2026-10-19. 이번 범위는 조사와 설계 제안이며 앱 코드는 변경하지 않는다.

## 결론

현재 몰입 보기는 **큰 상품 카드에서 사진을 교체하는 화면**이다. 원하는 경험은 **손가락을 따라 화면 전체가 위로 밀리고 다음 상품이 아래에서 올라와 한 장씩 안착하는 세로 피드**다. 사진이냐 영상이냐보다 화면을 넘기는 구조의 차이가 크다.

일반 보기는 그대로 두고, 몰입 보기만 별도의 전체 화면 탐색 공간으로 재설계하는 것을 권장한다. 상품 데이터·찜·언어·상세 이동·모드 기억은 재사용한다. 영상 업로드나 AI 추천을 추가하지 않아도 사진만으로 이 탐색감을 만들 수 있다.

## 현재 화면이 원하는 느낌과 다른 이유

현재 로컬 화면과 `app/for-you/ImmersiveProduct.tsx`, `ForYouContent.tsx`를 대조했다.

| 항목 | 현재 구현 | 권장 방향 |
| --- | --- | --- |
| 화면 점유 | 소개·보기 버튼·카테고리 아래에 둥근 상품 카드 | 몰입 중에는 사진 중심의 한 화면 한 상품 |
| 손가락 반응 | 터치 종료 후 이동 거리 60px 이상이면 상품 ID 변경 | 움직이는 동안 현재·다음 카드가 함께 이동 |
| 전환 | 같은 위치에서 이미지·텍스트가 즉시 교체됨 | 기존 카드가 위로 나가고 다음 카드가 아래에서 들어옴 |
| 멈춤 | 손을 놓은 뒤 다음 상품으로 즉시 변경 | 스크롤 관성 후 가까운 상품의 시작점에 안착 |
| 상품 정보 | 사진 아래 또는 옆에 별도 정보 패널 | 사진 아래쪽에 읽기 쉬운 얇은 정보 오버레이 |
| 주요 조작 | 이전·다음 큰 버튼과 사진 안 터치 영역 | 자연스러운 세로 스크롤이 주 조작, 버튼은 보조 |
| PC 입력 | 휠은 페이지를 스크롤하며 상품 자체를 넘기지 않음 | 피드 영역의 휠·트랙패드로 상품을 넘김 |

사진 영역은 현재 `h-[min(58svh,38rem)]`이고 바깥 여백·설명·버튼이 추가된다. `touch-pinch-zoom`과 touchEnd 계산으로 상품을 바꾸지만 연속된 세로 스크롤 트랙은 없다. 모바일 이미지 스와이프가 테스트를 통과했더라도, 그 테스트는 상품 변경을 증명한 것이지 Reels 같은 이동 감각까지 증명한 것은 아니다.

## 공식 자료에서 가져올 원칙

Meta는 Reels를 세로 피드에서 콘텐츠를 발견하고 좋아요·공유 등을 하는 경험으로 소개한다. 해당 자료는 2020년 출시 발표이며, 현재 앱의 모든 픽셀·제스처 규격을 정의하는 문서는 아니다. Potata의 화면 배치·전환 설계는 이를 참고한 제안이다. [Meta Reels 소개](https://about.fb.com/news/2020/08/introducing-instagram-reels/)

웹에서는 CSS Scroll Snap으로 스크롤이 특정 카드 위치에 멈추게 할 수 있다. 스크롤 자체가 연속적으로 이동하므로, 손을 놓은 뒤 이미지를 교체하는 현재 방식과 다르다. 브라우저마다 물리적 감속은 달라 Instagram 네이티브 앱과 완전히 같은 감각을 보장할 수는 없다. [MDN Scroll Snap](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Scroll_snap/Basic_concepts)

`touch-action`은 브라우저가 처리할 터치 동작을 결정한다. 다음 버전은 세로 스크롤을 브라우저에 맡기고 현재 세로 touchEnd 상품 변경은 제거하는 편이 좋다. 같은 제스처를 브라우저 스크롤과 JavaScript 이동이 동시에 처리하면 두 번 이동하거나 취소될 수 있다. [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)

`overscroll-behavior`는 피드 끝에서 바깥 페이지로 스크롤이 이어지는 현상을 제어한다. 몰입 피드와 일반 페이지를 동시에 움직이지 않게 설계하되, 명확한 나가기·언어·Footer 경로를 제공해야 한다. [MDN overscroll-behavior](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior)

## 권장 화면

모바일에서는 브라우저의 사용 가능한 높이를 채운다. 실제 기기 전체 화면을 요구하는 Fullscreen API나 별도 권한은 필요하지 않다. 기본 사이트 Navbar·큰 소개 문구는 몰입 영역 뒤로 숨기고, 상단에 일반 보기 복귀·카테고리만 작게 둔다.

- 중앙: 한 상품의 사진. 손으로 위아래로 밀면 다음·이전 상품이 연속해서 나타남.
- 오른쪽: 기존 찜, 상품 링크 공유. 새 댓글 시스템이나 가짜 반응 수치는 넣지 않음.
- 하단: 브랜드·상품명·실제 AED 가격·품절 표시와 기존 상세로 가는 버튼.
- 사진이 여러 장이면 좌우로 사진 이동, 작은 페이지 점과 좌우 보조 버튼. 세로 상품 이동과 축을 분리함.
- 항상 접근 가능한 작은 Language 드롭다운과 Footer 정보 버튼. 화면 맨 끝을 찾아 내려갈 필요가 없음.
- 마지막 상품 다음에는 “모두 봤어요” 종료 패널. 다시 보기·일반 보기 선택을 제공하고 첫 상품으로 몰래 순환하지 않음.

PC에서는 세로 사진 피드를 중앙에 두고 양옆은 어두운 여백으로 처리한다. 사진을 가로로 늘리지 않는다. 휠·트랙패드·방향 버튼·키보드를 지원하고, 정보가 길면 상세나 별도 패널로 열어 한 화면 높이를 깨지 않게 한다.

사진 위 글자는 그라데이션과 충분한 대비로 읽히게 하되 상품을 크게 가리지 않도록 한다. 사진은 기본적으로 전체 상품이 보이게 맞추고, 비율이 다른 사진을 Reels 비율에 억지로 잘라 소매·밑단·상품 정보를 숨기지 않는다. 몰입감은 사진 확대보다 뷰포트와 이동 방식으로 만든다.

## 전환 동작 제안

1. 일반 보기에서 몰입 보기로 바꾸면 현재 보던 상품이 전체 화면 피드의 기준 위치가 된다.
2. 위로 천천히 밀면 현재 상품이 손가락과 함께 올라가고 다음 상품이 밑에서 보인다.
3. 충분히 이동하면 다음 상품에 안착하고, 짧게 움직였다 놓으면 현재 상품으로 돌아온다. native snap의 판정은 브라우저가 처리한다.
4. 반대로 아래로 밀면 이전 상품으로 돌아간다. 첫 상품·마지막 종료 패널에서는 더 진행하지 않는다.
5. 일반 보기로 나가면 같은 상품의 격자 위치로 복귀한다. 카테고리·언어·사진 번호와 찜 상태를 유지한다.

이는 제안 동작이며 아직 구현된 상태가 아니다. 초기에 강제 전환 시간·거리·속도 수치를 고정하기보다 실제 iPhone·Android·트랙패드에서 감각을 비교해야 한다.

## 구현 방식 비교

| 방식 | 장점 | 위험 | 판단 |
| --- | --- | --- | --- |
| 현재 방식에 애니메이션만 추가 | 변경이 상대적으로 작음 | 손가락 추적·관성·휠 탐색이 계속 어색함 | 임시안으로도 비권장 |
| native 세로 스크롤과 CSS Scroll Snap | 실제 연속 이동·관성·터치와 휠을 기본 제공 | 브라우저별 차이와 중첩 가로 스크롤 검증 필요 | **첫 구현 권장** |
| 전용 제스처 엔진과 transform 트랙 | 이동 거리·속도·안착을 세밀하게 조절 | 확대·접근성·휠·취소·바운스·포커스를 직접 관리 | native 시제품이 부족할 때만 검토 |

권장 구조는 높이가 정해진 세로 스크롤 컨테이너와 화면 높이의 상품 슬라이드다. `scroll-snap-type: y mandatory`, 상품의 `scroll-snap-align: start`, 필요 시 `scroll-snap-stop: always`를 실험한다. 이 속성만으로 모든 기기에서 한 번의 휠 입력이 반드시 한 상품만 이동한다고 약속하지 않는다. [MDN snap stop](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scroll-snap-stop)

현재 단일 카드를 교체하는 구조를 유지한 채 CSS만 덧붙이지 말고, 연속된 슬라이드 위치가 존재하도록 바꿔야 한다. 작은 현재 카탈로그에서는 슬라이드의 공간을 유지하고 실제 고해상도 사진은 현재·인접 상품만 로드한다. 상품 수가 커진 뒤에는 높이를 보존하는 가상화와 cursor를 별도 설계한다. 스크롤 중 앞 상품 DOM을 제거해 화면이 튀는 방식은 피한다.

현재 상품 상태는 안정적으로 안착한 슬라이드를 기준으로 갱신하고, 오래된 observer·스크롤 응답이 현재 상품을 되돌리지 않게 한다. `scrollend`나 snap 이벤트 하나에만 의존하지 않고 대상 브라우저 지원을 확인해 대체 경로를 둔다. 사진별 번호는 상품 ID별로 유지한다.

## 기존 기능 보존과 변경 경계

- 일반 격자·ProductCard·HeartButton·상품 상세·가격·카테고리·번역·저장 상태는 재사용한다.
- 몰입 피드만 전체 화면 컨테이너로 바꾼다. 기존 페이지 밖 스크롤을 계속 허용하던 첫 계획과 달라지는 부분이다.
- 몰입 중 배경 페이지 스크롤을 제한한다면 진입 전 위치를 저장하고, 나가기·페이지 이동·오류·unmount 때 반드시 복원한다. 일반 보기의 스크롤은 제한하지 않는다.
- Footer를 없애지 않는다. 몰입 안의 Language와 Footer 열기를 공통 컴포넌트에 연결하고, 나가면 기존 Footer로 돌아온다. Provider나 장바구니 상태를 복제하지 않는다.
- 전체 화면을 dialog로 구현하면 접근 가능한 이름·닫기·포커스 복원·배경 비활성화를 함께 구현한다. 단순 fixed 레이어로 포커스를 뒤 페이지에 방치하지 않는다.
- 이 변경에 영상·추천 알고리즘·새 analytics·댓글·결제·DB migration은 필요하지 않다. 실제 상품을 무한 복제하거나 구매를 자동 실행하지 않는다.

## 이번에는 어떻게 검증해야 하는가

이전 테스트의 “상품이 바뀐다”보다 다음 감각을 완료 기준으로 삼아야 한다.

- 실제 native 터치 드래그 중 현재 상품의 화면 위치가 변하고, 손을 떼기 전 다음 상품 일부가 나타남.
- 짧은 드래그 취소·정상 드래그·빠른 연속 드래그·반대 방향 드래그가 튀거나 이중 이동하지 않음.
- 멈춘 뒤 한 상품이 뷰포트를 채우고 중간 위치에 걸리지 않음. 큰 글자·화면 회전·주소창 높이 변화에도 조작 가능.
- 세로 상품 이동과 가로 다중 사진 이동이 서로 오작동하지 않음. 실제 다중 사진 테스트 fixture를 마련하며 기존 상품 DB를 임의 변경하지 않음.
- Android Chrome·실제 iPhone Safari·데스크톱 트랙패드/휠을 구분해 확인. Chromium 모바일 에뮬레이션만으로 Safari 통과를 주장하지 않음.
- 일반 보기 복귀·상세 왕복·언어 변경·카테고리 변경 후 위치와 상태 유지.
- 이전·다음·나가기·Language를 키보드와 스크린리더로 사용 가능. reduced-motion에서는 프로그램 이동 애니메이션 축소, 확대는 차단하지 않음.
- 사진 실패·빈 목록·한 상품·마지막 상품 처리, 장시간 탐색 메모리·네트워크·불필요한 상세 조회 집계 확인.

## 추천하는 다음 순서

먼저 **몰입 보기만 전체 화면 세로 snap 시제품으로 교체**하고, 실제 터치에서 움직임을 사용자에게 확인받는다. 이 감각이 맞으면 찜·상세·언어·상태 복원을 연결하고 회귀 검증한다. 기존 두 보기 구조를 버리거나 상품 데이터를 새로 만들 필요는 없다.

분량은 몰입 컨테이너·카드 배치·탐색 상태 연결·테스트를 다루는 중간 이상 변경이며, 복잡도는 medium이다. 이미지·가로 제스처·모바일 Safari까지 포함하면 검증 난이도는 높아진다. 구현 전에 기존 실행 계획의 단일 카드·페이지 스크롤 유지 원칙을 이 새 방향에 맞춰 갱신해야 한다.

보고서만 작성했으며 기존 앱 코드·DB·운영 설정·커밋·배포는 변경하지 않았다.

## 승인 후 실행 계획

2026-10-19 사용자 승인: 보고서대로 전체 화면 세로 이동 구현, 일반 보기와 기존 기능 유지, 테스트 후 로컬 화면 제공. 앞 절의 미구현 상태는 조사 시점 기록이다.

### 고정한 결정과 경계

- 기존 For You 일반 격자/서버카탈로그/찜/가격/상세/카테고리/언어를 재사용한다. 기존 미커밋 dual-view를 이어서 수정하고 버리지 않는다.
- 몰입은 전체 뷰포트의 접근 가능한 dialog와 native 세로 스크롤/snap 구조로 구현한다. 브라우저 Fullscreen 권한은 요청하지 않는다.
- 배경 스크롤·포커스를 제한하되 Escape/일반 보기/페이지 이동/unmount 때 정확히 해제·복원한다. 뒤 배경의 Navbar·Footer에 포커스가 새지 않는다.
